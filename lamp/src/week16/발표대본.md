**⑥ 감상 '혹평' 클릭 → `pref_sentiment`**
- 감상 필터에서 **'혹평'** 을 누른다.
- 👀 `pref_sentiment` 가 생긴다. 정렬과 **똑같은 모양**이다.
- 💬 *"성격이 같은 값은 **같은 방식으로** 저장합니다. 서로 다르게 만들면

**⑦ 글 수 '50' 클릭 → `per_page`**
- 목록 위의 **15 / 30 / 50** 중 **50** 을 누른다. 한 화면에 글이 더 많이 뜬다.
- 👀 `per_page = 50` 이 생긴다.
- 💬 *"여기서 중요한 건 — **'숫자니까 안전하다'가 아니라 '우리가 정한 값인가'가 기준**이라는 겁니다.
  그냥 썼으면 주소에 `?per=100000` 을 넣어 서버를 갈아버릴 수 있어요."*
- (여유가 있으면) 주소창에 직접 `&per=100000` → **👀 15개로 되돌아온다**

**⑧ 상단바에서 아무거나 검색 → `recent_search`**
- 상단 검색칸에 작품 이름을 넣고 검색한다.
- 👀 `recent_search` 가 생긴다. 값이 **JSON 배열**이다 — 한글이 그대로 보인다.
- 💬 *"여러 개를 한 칸에 담아야 해서 JSON으로 넣었습니다. 최근 본 글은 숫자뿐이라 콤마로 이었고요.
  **담는 값의 모양에 따라 저장 방식도 달라집니다.**"*

**마무리 — 목록 전체를 한 번 짚는다**

## 📦 이번 주차에 만든 것 전부 (질문 대비 · 발표 후반부용)

> "쿠키와 세션을 썼습니다"가 아니라 **"이 기능들을 만들었고, 그러려면 쿠키와 세션이 필요했습니다"** 로 말한다.

### 세션에 둔 것 — 4개, 전부 **고치면 이득을 보는 값**

- **로그인 신원** (`user_id`) — 고치면 **남이 된다.** 지난주의 `?as=` 제거
- **CSRF 토큰** — 고치면 **방어가 뚫린다.** **POST 처리 19곳 · 폼 21곳** 전부. week15엔 **만들 수조차 없었다**
- **민감 작업 재인증**(`auth_at`) — 고치면 **비번 없이 영구삭제.** 15분 창
- **자동 로그아웃**(`last_seen`) — 고치면 **영원히 로그인.** 20분 유휴

> ★ **뒤의 둘이 핵심** — **시계를 사용자가 들고 있으면 그건 시계가 아니다.**

### 쿠키에 둔 것 — 11개, 고쳐봐야 **자기 손해뿐**

**오래 남는 것 (만료일 있음)**

- **정렬·감상 필터 · 한 페이지 글 수** — 사용자가 **탭을 눌러 고른** 설정
- **최근 검색어 · 최근 본 글 · 최근 본 작품 · 🆕 배지**(`last_visit`) — ★ **동의를 받아야 심는다**
- **쿠키 동의**(`consent`) — 무엇에 · 언제 · 어떤 방침 버전에 (+ 익명 `consent_id`)

**다음 한 요청만 사는 것 (만료 없음 = 창 닫으면 소멸)** — `handoff.php`

- **알림**(`flash`) · **로그인 후 목적지**(`intended`) · **폼 입력값**(`old_input`)
- ★ 셋 다 **처음엔 세션에 있었다.** 기준을 다시 대보니 *"고쳐도 자기 손해뿐"* 이라 내보냈다

### DB에 둔 것 — 주인이 '회원'이거나, **나중에 증명해야 하는** 값

- **글쓰기 초안**(`drafts`) — **💾 임시저장** 버튼. **창을 닫아도, 다른 기기에서도** 이어 쓴다
  *(세션 + 자동 저장이었다가 두 번 바꿨다 — 세션은 창 닫으면 사라져서 표로, 자동 저장은 언제 됐는지 몰라서 버튼으로)*
- **쿠키 동의 증빙**(`consent_log`) — ★ **고치지 않고 쌓기만 한다.**
  철회도 **새 줄**로 남긴다 — *'동의했다가 철회함'* 과 *'동의한 적 없음'* 은 **다른 사실**
- **로그인 실패 기록**(`login_attempts`) — **공격자가 0으로 되돌리고 싶은 값**이라 서버에.
  판정용이라 **15분 지나면 버린다** (증빙과 정반대)
- **로그인한 기기**(`user_devices`) — ★ **세션과 분리했다.** 세션은 30분이면 죽지만
  기기 기록은 남아야 한다 (*"지난주 PC방 로그인 끊기"*). `device` 쿠키로 알아본다
- **조회수 중복 방지**(`post_views`) — ★ **세션에서 옮겼다.** 세션엔 **시각이 없어서**
  *"몇 시간 뒤에 다시 셀지"* 를 정할 수가 없었다. Discourse와 같은 구조(하루 1회)

### 저장소 자체를 바꾼 것

- **세션을 임시 파일 → DB 표(`sessions`)로** — `SessionHandlerInterface` 6개 메서드.
  `$_SESSION`을 쓰는 코드는 **한 글자도 안 고쳤다**
- 그래서 가능해진 것: **`WHERE user_id = ?` 한 줄로 이 회원의 모든 세션 폐기**
  (비밀번호 변경 시 자동 실행). **파일이었으면 남의 기기 세션을 찾을 방법이 아예 없다**

### ★ 만들었다가 **없앤 것** — 이번 주차에서 가장 오래 고민한 부분

- **자동 로그인**(`remember_tokens`) — 004에서 만들고 **009에서 지웠다**
  - 쿠키엔 토큰, DB엔 지문, 쓸 때마다 회전, **재사용 탐지(계열)** 까지 만들었다
  - 그런데 **탐지는 주인이 그 자리로 돌아와야 작동**했다 → **완화는 되지만 해결은 안 된다**
  - → **"오래 사는 열쇠를 맡기지 않는다"** 로 결론. 훔칠 수 있는 게 **30일 → 20분**
- **로그인 기기 목록 · 기기별 로그아웃** — 이번 프로젝트에 필요 없다고 판단
- 💬 **"만들었다가 없앴다"가 "안 만들었다"보다 강하다** — 마이그레이션이 그 판단을 이력으로 남긴다

### 지운 것 — 새로 만든 기능보다 지운 코드가 더 많다

- `IDENTITY_KEY` · `identity_from_request()` · `identity_params()`
- `header.php`의 **URL 리라이터** · `main.js`의 `withIdentity()`
- `FLASH_KEYS` · `flash_pending()` · `flash_params()` → **`redirect()`가 두 줄로 줄었다**
- `UNDO_TARGETS`는 남았지만 성격이 바뀜: **보안 화이트리스트 → 버튼 설정표**
- ★ **로그인하는 길이 하나가 되면서 예외도 사라졌다** —
  *"쿠키로 되살아난 세션은 재인증 창을 안 열어준다"* 는 특례가 통째로 없어졌다

### 숫자

- **DB 표 8개 → 14개** — `sessions`(005) · `drafts`(006) · `consent_log`(007) ·
  `login_attempts`(010) · `user_devices`(011) · `post_views`(012)
  *(`remember_tokens`는 004에서 만들었다가 **009에서 삭제**)*
- **세션 열쇠 5개** — `user_id` · `csrf_token` · `viewed_posts` · `auth_at` · `last_seen`
- **우리가 심는 쿠키 11개** — `pref_sort` · `pref_sentiment` · `per_page` · `recent_search` ·
  `recent_posts` · `recent_works` · `last_visit` · `consent` · `flash` · `intended` · `old_input`
  (+ PHP가 심는 `PHPSESSID`)
- **접속은 HTTPS** — http(8081)로 들어오면 **302로 https(8443)** 로 보낸다.
  `'secure' => !empty($_SERVER['HTTPS'])` 를 처음부터 써둬서 **PHP 코드는 한 줄도 안 고쳤다**

### 고친 버그 (만들면서 실제로 겪은 것)

- 글 등록 **성공 후에도** 입력값이 남아 다음 글쓰기에 되살아남 → 성공 경로에서 직접 삭제
- 초안이 **새로고침에 날아감** → `sendBeacon`으로 막았다가, 결국 **버튼 방식**으로 정리
- 초안을 세션에 들고 있어 **payload가 비대해질 위험** → 길이 상한 → 결국 **DB 표로 이전**
  *(본문 5,000자 × 한글 3바이트 = 15KB, 세션 payload는 TEXT 65KB 한계)*
- `auth_at`이 매 요청 갱신돼 **sudo 창이 안 닫히던 것** → 유휴 시각만 갱신하도록 분리
- `setcookie()`를 화면 다 그린 뒤에 불러 **조용히 실패**(🆕 배지) → 헤더는 본문보다 먼저 나간다
- `$perPage`를 쓰는 곳보다 뒤에서 정의해 **0으로 나누기** → 파라미터 처리는 화면 계산보다 앞에

> **틀리면 손해 보는 것은 세션, 틀려도 취향일 뿐인 것은 쿠키.**"

- **세션 열쇠 4개 · 우리가 심는 쿠키 12개** (`device` 포함, + PHP가 심는 `PHPSESSID`)

  *(`remember_tokens`는 004에서 만들었다가 **009에서 지웠다** — 되돌린 판단도 이력에 남는다)*
- **지운 것** — `IDENTITY_KEY`·`identity_from_request()`·`identity_params()` /
  `header.php`의 URL 리라이터 / `main.js`의 `withIdentity()` /
  `FLASH_KEYS`·`flash_pending()`·`flash_params()`

> "그리고 이번 주에 **새로 만든 기능보다 지운 코드가 더 많습니다.**
> 지난주에 '세션 없이 해보자'를 끝까지 밀어붙였더니 한계가 코드에 흉터로 남았고,

> 맞습니다. 번호표(PHPSESSID)를 쿠키로 주고받아요.
> 그래서 정확히 말하면 "세션이냐 쿠키냐"가 아니라 **"값을 어디에 두느냐"**의 차이입니다.
> 세션은 값이 서버에, 쿠키는 값이 사용자 PC에 있습니다.

**Q. 세션은 서버 어디에 저장되나요?**
> 기본값은 서버의 임시 파일입니다. 규모가 커지면 Redis 같은 별도 저장소로 옮기고요.
> 중요한 건 **위치가 아니라 '사용자가 못 건드리는 곳'이라는 사실**입니다.

**Q. 비밀번호는 왜 토큰처럼 SHA-256을 안 쓰나요?**
> 용도가 다릅니다. 비밀번호는 **사람이 만들어서 짧고 흔해요.** 그래서 일부러 느린
> `password_hash`로 대입 공격을 어렵게 만듭니다.
> 토큰은 우리가 만든 32바이트 무작위값이라 대입이 애초에 불가능하고,
> 게다가 `password_hash`는 값마다 소금이 달라서 **'해시로 찾기'가 안 됩니다** — 전부 훑어야 해요.

**Q. 자동 로그인이 보안상 위험하지 않나요?**
> 위험을 줄이는 장치를 넷 걸었습니다.
> ①쿠키엔 원본, DB엔 해시 ②쓸 때마다 토큰 회전 ③`HttpOnly`로 JS 차단 ④30일 만료.
> 그래도 세션보다 위험한 건 맞아서, 로그인 화면에 **"공용 PC에서는 체크하지 마세요"** 를 적어뒀습니다.

**Q. `SameSite=Lax`가 있는데 CSRF 토큰이 왜 또 필요한가요?**
> `SameSite`는 **브라우저가 지켜주는** 방어입니다. 낡은 브라우저나 예외 상황에서 뚫려요.
> 서버가 스스로 확인하는 쪽이 진짜 방어라 둘 다 겁니다. 이미지 업로드 막을 때와 같은 **다층 방어**예요.

**Q. 조회수를 새 창으로 열면 또 오르지 않나요?**
> 안 오릅니다. 판정을 `post_views` 표로 옮겨서 **하루에 한 번**만 셉니다.
> 브라우저를 닫아도, 쿠키를 지워도(같은 접속지면) 안 올라갑니다.

**Q. 그래도 완전히는 못 막지 않나요?**
> 맞습니다. **다른 네트워크에서 쿠키를 지우면** 셀 수 있어요.
> 완전히 막으려면 **브라우저 지문을 채취**해야 하는데, 그건 **저희가 만든 동의 기능과 앞뒤가 안 맞습니다.**
> **완벽한 익명 식별자는 없다**는 게 결론이었고, **부풀리기 비용을 올리는 데까지**가 저희 선택입니다.

**Q. 봇은요?**
> 봇에게는 **세션도 안 만들고 조회수도 안 셉니다.** 재봤더니 쿠키를 안 받는 상대 30요청에
> **세션 행이 30개** 쌓이더군요. 다만 판별은 User-Agent라 **숨기는 봇은 못 잡습니다** —
> **보안 장치가 아니라 청소 장치**입니다.
