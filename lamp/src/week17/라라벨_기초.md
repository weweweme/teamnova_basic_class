# Laravel — 무엇을 알아야 하나

Laravel을 처음 쓰는 사람이 이관 작업 전에 알아 둘 것.
Unity·Android Studio를 써 봤다면 대부분 이미 겪어 본 구조다.

## 0. 큰 그림 — 이미 겪어 본 구조다

- Unity에서 `main()` 을 직접 쓰지 않는다. `Start()` · `Update()` 를 **Unity가 불러 준다.**
- Android에서도 화면을 직접 실행하지 않는다. `onCreate()` 를 **시스템이 불러 준다.**
- **Laravel도 똑같다.** 진입점은 프레임워크가 갖고 있고, 우리는 **불려 나갈 자리**만 채운다.
- 지금 우리 프로젝트는 반대다 — `post/view.php` 가 **스스로 시작해서 스스로 끝낸다.**

## 1. 요청 하나가 처리되는 흐름

### 지금 우리 프로젝트 — 주소가 곧 파일

1. 브라우저가 `/post/view.php?id=3` 요청
2. Apache가 **그 파일을 직접 실행**
3. 파일 안에서 `require_once` → `require_login()` → DB 조회 → HTML 출력

> 비유 — **매니페스트 없이 화면 파일을 직접 여는 것.** 안드로이드에서는 아예 불가능한 방식이다.

### Laravel — 주소와 파일이 분리됨

1. 브라우저가 `/posts/3` 요청
2. Apache는 어떤 주소든 **항상 `public/index.php` 하나만** 실행 (그래서 문서 루트가 `public/`)
   - 비유 — Unity 게임이 어떤 씬으로 시작하든 **실행 파일은 하나**인 것과 같다
3. 프레임워크가 부팅되고, `routes/web.php` 에서 `/posts/{id}` 규칙을 찾는다
   - 비유 — **`AndroidManifest.xml` 의 `<activity>` 등록.** 등록하지 않은 주소는 존재하지 않는다
4. 그 주소에 걸린 **미들웨어**를 통과 (로그인 확인·CSRF 검사가 여기서 일어난다)
5. **컨트롤러** 메서드 실행 → **모델**로 DB 조회 → **뷰**에 값 전달
6. Blade가 HTML을 만들어 응답

## 2. 알아야 할 개념 6개

| 개념 | 하는 일 | 지금 우리 코드 | 비유 |
|---|---|---|---|
| **라우트** `routes/web.php` | "이 주소로 오면 이 코드" 목록 | 파일을 만들면 그게 곧 주소였다 | `AndroidManifest.xml` 의 화면 등록 |
| **컨트롤러** `app/Http/Controllers/` | 요청을 처리하는 클래스 | `post/view.php` | **Activity 클래스** / Unity MonoBehaviour |
| **모델(Eloquent)** `app/Models/` | 표 하나 = 클래스 하나 | `includes/posts.php` 의 SQL 조립 | Room의 `@Entity` + DAO |
| **Blade 뷰** `resources/views/` | 화면. `{{ }}` 는 escape 자동 | `<?= e(...) ?>` 를 손으로 | `res/layout/*.xml` |
| **미들웨어** | 컨트롤러에 닿기 전 검사 | `require_login()` · `require_csrf()` | OkHttp **Interceptor** |
| **artisan** | 파일 생성·상태 확인·캐시 정리 | 없음 (파일 복사로 대체) | **File → New → Activity** + Gradle |

- 뷰에 대해 하나 더 — 지금 우리는 로직과 HTML이 한 파일에 섞여 있다.
  **Activity 코드 안에서 뷰를 전부 `new` 로 만드는 상태**와 같다.

## 3. 폴더 — 무엇이 어디에 있나

| 폴더·파일 | 역할 | 비유 |
|---|---|---|
| `public/` | **웹에 노출되는 유일한 폴더.** `index.php` 와 CSS·JS·이미지 | Unity 빌드 산출물 폴더 |
| `routes/web.php` | 주소 목록 | `AndroidManifest.xml` |
| `app/Http/Controllers/` | 요청 처리 코드 | Activity |
| `app/Models/` | 표에 대응하는 클래스 | Room Entity/DAO |
| `resources/views/` | 화면 파일 `.blade.php` | `res/layout/` |
| `config/` | `.env` 값을 정리해 둔 설정 | `BuildConfig` |
| `.env` | 기기마다 다른 값. **git 제외** | `local.properties` |
| `storage/` | 로그·컴파일된 화면·캐시. **쓰기 권한 필요** | Unity `Library/` · Android `build/` |
| `vendor/` | 설치된 라이브러리. **직접 고치지 않는다** | Unity `Packages/` · Gradle 의존성 |
| `composer.json` / `.lock` | 의존성 목록 / 버전 고정 | `build.gradle` / lockfile |
| `bootstrap/app.php` | 미들웨어·라우트 등록 지점 | — |
| `artisan` | 명령 도구 진입점 | — |

> 설치 직후 500 에러가 났던 원인이 `storage/` 쓰기 권한이었다. Apache가 `daemon` 사용자로 돌기 때문.

## 4. 실제로 칠 명령 (우리 환경)

호스트에는 PHP가 없으므로 **컨테이너 안에서** 실행한다.

```bash
docker exec -w /var/www/html/week17 manual_lamp /usr/local/php/bin/php artisan <명령>
```

| 명령 | 쓰임 | 비유 |
|---|---|---|
| `route:list` | 등록된 주소 전부 보기 | 매니페스트를 펼쳐 보기 |
| `make:model Post` · `make:controller PostController` | 뼈대 생성 | New → Activity |
| `tinker` | 한 줄씩 실행해 보는 콘솔 | 플레이 모드에서 값 찍어 보기 |
| `config:clear` | 설정을 고쳤는데 반영이 안 될 때 | `Library/` 지우고 다시 열기 |
| `db:show` · `db:table posts` | DB 상태 확인 | — |

## 5. 학습 순서 — 손으로 해보는 게 빠르다

1. `routes/web.php` 에 한 줄 넣고 아무 화면이나 띄우기
   → 매니페스트에 Activity 하나 등록해 보는 것
2. 그 화면에 값을 넘겨 Blade로 출력
   → layout XML에 텍스트 바인딩해 보는 것. `{{ }}` 의 자동 escape를 여기서 확인
3. `Post` 모델을 만들고 `tinker` 에서 `Post::count()`
   → **190이 나오면** 기존 DB가 그대로 붙은 것이다
4. `Post::paginate(15)` + `{{ $posts->links() }}`
   → 이번 주차 과제의 핵심이 여기서 끝난다

1~4가 곧 [리팩토링_설계.md](리팩토링_설계.md) 의 **1단계**다.
