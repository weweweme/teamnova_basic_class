# week17 — Laravel 이관 설계

현재 프로젝트(PHP 직접 작성, 파일 80개 · 9,717줄)를 Laravel 13으로 전부 옮기기 위한 설계다.
Laravel 13.31.0 설치와 기존 MariaDB 연결까지는 끝난 상태에서 작성했다.

## 1. 원칙

- **DB는 손대지 않는다.** 기존 표 15개를 그대로 쓰고 Laravel 마이그레이션은 돌리지 않는다.
- **버릴 것과 옮길 것을 먼저 가른다.** 우리가 짠 코드 상당수는 Laravel 방식으로 다시 쓰는 게 아니라,
  **대응 기능이 이미 있어 삭제된다.**
  - *옮긴다* = 우리 로직을 Laravel 방식으로 다시 쓴다 (로직이 남는다)
  - *버린다* = 파일을 지운다. 대응하는 우리 코드가 0줄이 된다
- **단계마다 브라우저에서 확인 가능한 상태로 끝낸다.** 한 번에 전부 바꾸지 않는다.
- **레거시 파일은 해당 기능이 옮겨질 때 지운다.** 그전까지는 남겨 두고 참고한다.

> ⚠ 버릴 때 동작이 완전히 같지는 않다. 예: 지금 `require_csrf()` 는 실패 시 우리가 정한 화면으로
> 보내지만 Laravel은 419 응답을 낸다. 그래서 단계마다 실제 화면 확인이 필요하다.

## 2. 확인된 호환성 (2026-09 측정)

| 항목 | 결과 | 영향 |
|---|---|---|
| 비밀번호 해시 | `$2y$12$` = bcrypt cost 12 | Laravel 기본 해시와 **그대로 호환**. 회원 25명이 비밀번호 변경 없이 로그인된다 |
| `sessions` 표 | `id_hash · last_active · device_id · expires_at` | Laravel 기본(`id · last_activity`)과 다름 → **커스텀 세션 드라이버 필요** |
| `likes` / `votes` | id 없는 복합키 | 모델보다 **관계(belongsToMany) + 피벗**으로 다룬다 |
| 수정 시각 컬럼 | `posts`·`comments` 는 `edited_at` | 모델에 `const UPDATED_AT = 'edited_at'` |
| 회원 시각 컬럼 | `users` 는 `joined_at` 하나 | `$timestamps = false` 또는 `CREATED_AT = 'joined_at'` |
| PHP 확장 | cURL·intl 없음 | **실측: cURL 없이 설치·구동됨.** Composer도 `allow_url_fopen` 으로 동작했다. `intl` 은 `db:show` 의 용량 표시 등 일부 기능에서만 필요 |

## 2-1. 설치하며 걸린 환경 문제 (다른 PC에서 또 겪는다)

이 컨테이너 이미지는 손으로 만든 것이라 Dockerfile이 없다. 아래 세 가지는 **재현 절차로 남겨 둔다.**

- **`storage` · `bootstrap/cache` 쓰기 권한**
  - 증상 — 첫 접속에서 500. `tempnam(): file created in the system's temporary directory`
  - 원인 — Apache 워커가 `daemon` 사용자로 도는데 두 폴더가 root 소유 755였다
  - 조치 — `chmod -R 777 storage bootstrap/cache` (컨테이너 재시작 후에도 유지되는 것을 확인)
  - 근거 — Laravel 배포 문서가 요구하는 조건이다
- **Apache `AllowOverride None` → `All`**
  - 증상 — `/` 는 되는데 `/hello` 는 **Apache의** 404 (Laravel 404 화면이 아님)
  - 원인 — Laravel은 `public/.htaccess` 의 재작성 규칙으로 모든 요청을 `index.php` 로 보내는데,
    `AllowOverride None` 이면 그 파일이 무시된다. `/` 만 되던 건 `DirectoryIndex` 가 `index.php` 를 직접 찾았기 때문
  - 조치 — `apache/httpd.conf` 의 `<Directory "${APP_DIR}">` 두 곳(http·https)을 `AllowOverride All` 로
- **Composer 보관 위치**
  - 컨테이너 안에 설치하면 `docker compose up -d` 로 다시 만들 때 사라진다
  - `src/_tools/composer.phar` 에 두어 bind mount로 살아남게 했다
  - 실행 — `docker exec -w /var/www/html/week17 manual_lamp /usr/local/php/bin/php /var/www/html/_tools/composer.phar <명령>`

- **모든 화면이 4~5초 (2026-09)**
  - 증상 — 화면 종류와 무관하게 응답이 4~5초. 버튼을 눌러도 반응이 없는 것처럼 보였다.
  - 좁혀 간 순서
    1. 순수 PHP 한 줄 파일: **0.02초** → Apache·PHP 자체는 정상
    2. Laravel 부팅만 측정: **2.8초** (autoload 0.5 / app 0.38 / bootstrap 1.9)
    3. OPcache 상태: **켜져 있고 적중률 99.2%** → 컴파일은 원인이 아님
    4. 파일 확인(stat) 비용 측정: **개당 1.11ms** (리눅스 파일시스템은 0.001ms 수준)
  - 원인 — 소스가 **Windows 바인드 마운트**(`./src`) 위에 있다.
    OPcache 기본값(`validate_timestamps=1`, `revalidate_freq=2`)은 매 요청 캐시된 파일의
    수정 시각을 확인하는데, Laravel은 요청당 파일 1,013개를 쓴다.
    **1,013 × 1.11ms ≈ 1.1초**, 여기에 설정·뷰 파일까지 더해져 4~5초가 됐다.
    컨테이너에 **php.ini 가 아예 없어서** PHP 내장 기본값으로 돌고 있었다.
  - 조치 — `docker/php.ini` 를 만들고 `entrypoint.sh` 가 복사한다 (Git 관리 → 다른 PC에도 적용).
    - `opcache.revalidate_freq = 60` — 확인을 **끄지 않고**(`validate_timestamps=1` 유지) 주기만 늘렸다.
      끄면 가장 빠르지만 고친 코드가 반영되지 않아 개발 중에는 쓸 수 없다.
    - `realpath_cache_size = 4096K` · `memory_consumption = 256` · `interned_strings_buffer = 32`
      (Symfony 성능 문서 권장값 — 발표 자료에서 인용한 그 값)
  - 결과 — `/` 4.9초 → **0.13초**, `/posts` 5.0초 → **0.29초**, `/login` 3.8초 → **0.13초**
  - ★ 발표용 — ④ 성능에서 프레임워크 간 1.5배 차이를 놓고 "우리 규모에선 체감 안 된다"고 판정했는데,
    실제 체감을 만든 것은 프레임워크가 아니라 **환경 설정 하나였고 그 차이는 약 30배**였다.
    Symfony를 골랐어도 똑같이 겪었을 문제다.

## 2-2. 기능은 옮겼는데 화면이 깨진 문제 (2026-09)

- **증상** — 모든 화면의 배치가 원본과 달랐다. 홈은 줄이 무너지고, 작품 게시판은
  포스터·제목·줄거리가 세로로 흩어졌으며, 쿠키 배너는 팝업이 아니라 화면 맨 아래에 붙어 있었다.
- **원인** — `style.css` 는 **레거시 HTML 구조를 전제로 쓰여 있다.**
  Blade 를 새로 쓰면서 클래스 이름을 내가 지어냈고(`work-header` · `vote` · `work-list` 등),
  중첩도 달라졌다. 스타일시트는 한 글자도 안 고쳤는데 붙을 자리가 없어진 것이다.
  - 확인 방법 — `style.css` 의 클래스 목록과 Blade 의 클래스 목록을 뽑아 양쪽 차집합을 봤다.
    · 뷰에만 있는 이름 = 내가 지어낸 것 (스타일이 없다)
    · CSS 에만 있는 이름 = 아직 안 옮긴 화면 조각
- **조치** — 화면마다 `git show <이관 전 커밋>:<레거시 파일>` 로 원본 마크업을 꺼내
  **클래스 이름과 중첩을 그대로** 옮겨 적었다. 겹치는 조각은 Blade 조각으로 한 벌만 뒀다.
  - `partials/board` — 전체 글 목록과 작품 게시판이 같이 쓴다
  - `partials/search-bar` · `search-works` · `search-posts` · `search-users` — 검색 네 화면이 같이 쓴다
  - `vendor/pagination/default` — Laravel 기본 출력이 Tailwind 용이라 우리 `.pagination` 구조로 바꿨다
- **덤으로 드러난 것** — 마크업을 맞추다 보니 **빠진 기능**도 같이 드러났다.
  등급 배지 기준(👑 시네필 … 🌱 새싹)이 달랐고, 랭킹 탭·프로필 탭·작품 상세(감독·출연·예고편)·
  쿠키 동의 기록이 통째로 없었다. 화면을 맞추는 일이 곧 누락 점검이 됐다.
- **★ 발표용** — "프레임워크가 화면을 만들어 주지는 않는다."
  Blade 가 줄여 준 것은 `e()` · `require` · 로그인 검사 같은 **반복**이지 화면 구조가 아니다.
  화면은 옮기는 사람이 원본을 보고 옮겨야 하고, 그래서 **옮길 원본이 남아 있어야 한다**
  (그래서 레거시 파일을 지우기 전에 git 에 남겨 두고 `git show` 로 꺼내 썼다).

## 5. 모델 설계

- `User`(users) — `$timestamps = false`, `CREATED_AT = 'joined_at'`
- `Post`(posts) — `SoftDeletes`, `const UPDATED_AT = 'edited_at'`
- `Comment`(comments) — `SoftDeletes`, `const UPDATED_AT = 'edited_at'`, 자기참조 `parent` / `replies`
- `Media`(media) — `$table = 'media'`, `$timestamps = false`
- `Notification` · `Report` · `Draft` · `Device` · `ConsentLog` · `LoginAttempt` · `PostViewDaily`

관계

- `Post belongsTo User·Media` / `Post hasMany Comment`
- `User belongsToMany Post` (likes) / `User belongsToMany Media` (votes, `choice` 피벗)

## 7. 결정이 필요한 것

- **로그인 식별자** — `users` 에 email이 없다. Laravel 기본 인증은 email 기준이라 **username 기반으로 바꿔 설정**해야 한다.
- **이관 중 레거시 확인 방법** — 문서 루트가 `public/` 이라 지금 옛 화면을 볼 수 없다.
  비교가 필요하면 `public/legacy` 심볼릭 링크를 두는 방법이 있다.
- **TMDB 호출 방식** — Laravel HTTP 클라이언트는 Guzzle을 쓰는데 우리 환경에 cURL이 없다.
  **stream 방식으로 도는지 1단계에서 먼저 확인**하고, 안 되면 기존 `tmdb.php` 호출부를 그대로 둔다.
