# 레거시 ↔ Laravel 비교 자료

발표 자료(레거시 vs 리팩토링)의 근거. **기능이 양쪽 같은 상태**에서 잰 값이다.

- 레거시 기준점 — 이관 직전 커밋 `d92bc54^` (`git show d92bc54^:<파일>` 로 언제든 다시 잴 수 있다)
- Laravel 기준점 — 화면 맞추기까지 끝낸 2026-09-12
- 재측정 — 2026-09-12. 화면을 레거시 마크업으로 맞추면서 Blade 가 늘어 첫 측정값과 달라졌다.

## 0. 세는 방법 (발표에서 물어보면 이대로 답한다)

- **레거시** — `.php` 전부. 단 Laravel 설치물(`app/` `resources/` `routes/` `config/` `vendor/` `public/index.php`)은 뺀다.
- **Laravel** — `app/` + `resources/views/` + `routes/` 만.
  `config/`(1,340줄)와 `vendor/`는 뺀다. **설정 기본값과 남의 코드는 '우리가 짠 양'이 아니다.**
- **양쪽에서 뺀 것** — `assets/` 의 CSS·JS. 옮긴 게 아니라 **그대로 쓴 것**이라 비교 대상이 아니다.
  (`style.css` 1,157줄은 한 글자도 안 고쳤고, `main.js` 586줄은 부르는 주소 3개만 바꿨다)

## 1. 규모

| 구분 | 파일 | 줄 |
|---|---|---|
| 레거시 — 화면·처리 | 45개 | 3,512줄 |
| 레거시 — includes 모듈 | 31개 | 5,744줄 |
| 레거시 — 루트 화면 | 3개 | 455줄 |
| **레거시 합계** | **79개** | **9,711줄** |
| | | |
| Laravel — `app/` (모델·컨트롤러·서비스·미들웨어·정책) | 45개 | 3,634줄 |
| Laravel — `resources/views/` (화면) | 30개 | 1,771줄 |
| Laravel — `routes/` | 2개 | 157줄 |
| **Laravel 합계** | **77개** | **5,562줄** |

- 파일 수는 거의 같고 **줄 수가 43% 줄었다.**
- 줄이 준 자리는 `includes/` 다. 5,744줄짜리 공용 모듈 31개가
  프레임워크 내장(인증·CSRF·세션·소프트삭제·페이징)으로 대체되면서 `app/Services/` 7개 1,047줄만 남았다.
- 파일 수가 안 준 이유 — 레거시는 화면 하나를 여러 파일로 쪼갰고(`write` `create` `update` `delete`),
  Laravel 은 컨트롤러 하나에 메서드로 모았다. 대신 **화면(Blade)이 30개로 늘었다.**
  줄어든 만큼 다른 데서 늘어난 게 아니라, **경계가 다른 곳에 그어진 것**이다.

## 2. 손으로 반복하던 것이 얼마나 사라졌나

| 항목 | 레거시 | Laravel | 무엇이 대신하나 |
|---|---|---|---|
| `e()` 직접 호출 | 243곳 | **4곳** | Blade `{{ }}` 자동 escape |
| `require_once` | 207곳 | 0곳 | Composer 오토로드 |
| `require_login()` | 26곳 | 0곳 | `auth` 미들웨어 (라우트에 23곳 지정) |
| `require_csrf()` | 25곳 | 0곳 | CSRF 미들웨어 기본 포함 |
| `WHERE deleted_at IS NULL` | 20곳 | 0곳 | `SoftDeletes` 글로벌 스코프 (모델 2개에 한 줄) |
| SQL 문자열을 직접 실행 | 79곳 | 0곳 | Eloquent · 쿼리 빌더 |
| 직접 쓴 SQL 조각 (`whereRaw` 등) | — | 11곳 | 아래 참고 |
| `<form` | 33개 | 28개 | 개수는 비슷하다 — 바뀐 건 **검사 방식**이다 |

> 세는 기준 — 호출 지점만 센다(함수 정의 한 줄은 뺀다). 주석에 이름만 나오는 줄도 뺀다.
> `SQL 문자열을 직접 실행` = `->prepare(` · `->query(` · `->exec(` 의 합.

### `e()` 가 4곳 남은 이유 — 여기가 발표 포인트다

Blade 의 `{{ }}` 는 **값을 그대로 내보내는 자리**를 자동으로 처리한다.
남은 4곳은 전부 **우리가 HTML 을 직접 만들어야 하는 자리**다. 자동이 닿지 않는 곳이 어디인지 정확히 보여준다.

| 자리 | 왜 손으로 하나 |
|---|---|
| `Support/Highlight.php` (2곳) | 검색어에 형광펜(`<mark>`)을 칠한다. **먼저 안전하게 만들고 그다음 태그를 넣어야** 한다 |
| `Models/User.php` — 등급 배지 | `<span class="lvl-badge" title="…">` 조각을 만들어 돌려준다 |
| `posts/show.blade.php` — 본문 | `nl2br()` 이 줄바꿈을 `<br>` 로 바꾸기 전에 안전 처리를 끝내야 한다 |

순서를 뒤집으면 둘 중 하나가 된다.
넣은 태그까지 글자로 변해 화면에 그대로 보이거나, 사용자가 넣은 `<script>` 가 진짜로 실행된다.

### `whereRaw` 11곳 — 줄어든 게 아니라 자리가 바뀐 것

SQL 문자열을 통째로 쓰는 일은 사라졌지만, **표현식 조각**은 남는다.

- `COALESCE(parent_id, id)` — 원댓글 바로 밑에 그 답글을 붙이는 정렬 (댓글 페이징의 핵심)
- `views + 댓글수 × 10` — '인기' 정렬 기준
- `FIELD(id, …)` — 최근 본 순서 그대로 세우기
- `SUM(views)` · `COUNT(*)` — 집계

전부 **우리 프로젝트의 규칙**이지 프레임워크가 알 수 있는 내용이 아니다.
이런 자리를 가리려고 쓰는 게 아니라, **여기만 남기려고** 쓰는 것이다.

## 4. 화면은 어떻게 달라졌나

처리 쪽과 달리 **화면은 줄지 않았다.** 여기가 이번 이관에서 제일 헷갈렸던 부분이다.

| 레거시 | Laravel |
|---|---|
| `includes/header.php` + `footer.php` 를 파일마다 `require` | `layouts/app.blade.php` 하나를 `@extends` |
| `includes/media_row.php` 의 `render_media_row()` 함수 | `partials/media-row.blade.php` 를 `@include` |
| `includes/search_ui.php` 의 렌더 함수 4개 | `partials/search-bar` · `search-works` · `search-posts` · `search-users` |
| `board/index.php` 안에서 if 로 갈라 쓰던 목록 | `partials/board.blade.php` 를 두 화면이 `@include` |
| 페이지 번호를 화면마다 손으로 그림 | `vendor/pagination/default.blade.php` 한 벌 + `{{ $posts->links() }}` |

- **줄 수는 1,771줄로 오히려 늘었다.** 레거시는 화면 조각이 `includes/` 에 함수로 섞여 있어서
  '화면'과 '처리'가 한 파일에 같이 있었다. Blade 로 옮기면서 화면이 화면 파일로 모인 것이다.
- **Laravel 이 줄여 준 것은 화면 구조가 아니다.** `e()` · `require` · 로그인 검사 같은 **반복**이다.
  클래스 이름과 중첩은 옮기는 사람이 원본을 보고 그대로 옮겨야 했다
  (그 과정에서 겪은 문제는 [리팩토링_설계.md](리팩토링_설계.md) 2-2 참고).

## 5. 성능 — 프레임워크 차이보다 큰 게 있었다

발표 ④ 성능 항목에서 Laravel·Symfony 사이 1.5배 차이를 놓고 "우리 규모에선 체감 안 된다"고 판정했다.
실제로 체감을 만든 것은 프레임워크가 아니라 **환경 설정 하나**였다.

| 화면 | php.ini 없을 때 | 넣은 뒤 |
|---|---|---|
| `/` | 4.9초 | 0.13초 |
| `/posts` | 5.0초 | 0.29초 |
| `/login` | 3.8초 | 0.13초 |

약 30배. Symfony 를 골랐어도 똑같이 겪었을 문제다. 원인과 좁혀 간 과정은 [리팩토링_설계.md](리팩토링_설계.md) 2-1 에 있다.
