# 라라벨 장치 탐색부터 기능 구현까지 — 정리

> week17 · 영화·드라마 리뷰 커뮤니티 (레거시 PHP → Laravel 13.31 이관 뒤 기능 추가)

이 문서는 **"프레임워크를 왜 쓰는가"에 답하기 위해 거친 세 단계**를 기록한 것이다.
라라벨이 주는 장치를 훑어 후보를 추리고, 그중 무엇을 만들지 고르고, 실제로 만들었다.
**고르지 않은 것과 그 이유도 함께 적는다** — 무엇을 안 만들지 정한 것도 판단이기 때문이다.

---

## 1단계 — 새 기능 후보 찾기

프레임워크에는 사용자가 쓰는 기능이 없다. **기능을 만들 장치**가 있을 뿐이다.
로그인 화면도, 메일 발송 버튼도 라라벨에는 없다. 그것을 만들 부품이 있다.

### 라라벨은 두 층이다

- **본체** — `laravel/framework`. 프로젝트를 만들면 처음부터 들어 있다
  - 라우팅 · Eloquent · 큐 · 예약 작업 · 알림 · 소프트 삭제 · 비밀번호 찾기 · 이메일 인증 · 서명된 URL · 페이징
- **공식 패키지** — `laravel/socialite`, `laravel/scout`, `laravel/sanctum` 등. **필요한 사람만 따로 받는다**
  - 같은 팀이 만들고, 공식 문서에 들어 있고, 프레임워크 판올림에 맞춰 관리된다
  - 모든 앱이 소셜 로그인을 쓰는 것은 아니라서 기본 설치에 넣지 않았을 뿐이다

> Unity 로 치면 엔진 본체와 Package Manager 로 받는 공식 패키지(Cinemachine, Input System)의 관계다.
> 같은 팀이 만들고 공식 문서에 있지만, 새 프로젝트에 기본으로 들어 있지는 않다.

**둘 다 '라라벨이 주는 것'이다.** 아래 목록에는 둘을 섞어 적되, 공식 패키지는 따로 표시했다.

그래서 공식 문서(Laravel 13.x)를 훑으며 이렇게 물었다 —
**"이 장치를 쓰면 사용자 눈에 보이는 기능이 하나 생기겠는가?"**

**여기 없는 것들** — 라우팅, Eloquent, 검증, 미들웨어, Blade, 세션.
라라벨의 중심에 있는 장치들이지만 **이관 단계에서 이미 쓰고 있다.**
그것들로는 새로 만들 기능이 없다. 있던 코드가 짧아졌을 뿐이다.

그래서 아래는 장치를 전부 나열한 목록이 아니라 **후보 목록**이다.
무엇을 만들지는 2단계에서 고른다.

### 인증

- **비밀번호 찾기** — `Password::sendResetLink()` / `Password::reset()`
  - 비밀번호를 잊은 사람이 **메일로 온 링크를 눌러 새 비밀번호를 정하는 절차 전체**를 맡는다
  - 하는 일은 네 가지다
    - 일회용 토큰을 만들어 `password_reset_tokens` 표에 **해시로** 저장한다.
      표를 들여다봐도 원래 토큰을 알 수 없다 — 비밀번호를 해시로 두는 것과 같은 이유다
    - 그 토큰이 담긴 링크를 메일로 보낸다
    - 링크를 누르면 토큰이 맞는지·만료되지 않았는지 확인한다
    - 새 비밀번호를 저장하고 쓴 토큰을 지운다 (같은 링크를 두 번 쓸 수 없다)
  - 우리가 적는 것은 '어떤 화면을 보여줄지'뿐이다
  - 공식 문서에는 **password broker**(비밀번호 중개자)로 나온다.
    토큰을 발급·검증·폐기하는 일을 **사이에서 대신 맡는다**는 뜻이다

- **이메일 인증** — `MustVerifyEmail` 계약(interface)
  - "이 주소가 정말 이 사람 것인가"를 확인하는 장치다. 적어 넣은 주소를 그대로 믿지 않는다
  - **계약** = "이 모델은 이런 일을 할 줄 안다"는 선언. 붙이기만 하면 구현은 부모가 이미 갖고 있다
  - 붙이면 세 가지를 쓸 수 있다
    - `hasVerifiedEmail()` — 확인됐나 (`email_verified_at` 칸이 채워졌나)
    - `markEmailAsVerified()` — 지금 시각으로 채운다
    - `sendEmailVerificationNotification()` — 확인 메일을 보낸다
  - 메일 속 링크에는 **서명과 만료 시각**이 들어 있고, 주소를 고치면 통하지 않는다
  - 링크의 해시는 **보낼 당시의 주소**로 만든다. 그 뒤 주소를 바꾸면 옛 링크는 죽는다

- **본인 재확인** — `password.confirm` 미들웨어
  - 로그인과 별개로 **"지금 이 순간 본인이 맞나"** 를 묻는다
  - 라우트에 붙이면, 최근 15분 안에 확인한 적이 없을 때 확인 화면으로 보낸다
  - 로그인한 채로 자리를 비운 사이 누가 설정을 바꾸는 것을 막는다

- **소셜 로그인** — `laravel/socialite` **(공식 패키지 · 따로 설치)**
  - 구글·깃허브 같은 곳에 "이 사람이 누구인지 확인해 달라"고 맡기는 절차(OAuth 2.0)를 대신해 준다
  - **절차가 네 단계다. 넷 다 Socialite 가 한다**
    - ① 구글로 보낼 주소를 규격대로 조립한다 — 우리 앱 번호 · 돌아올 주소 · 무엇을 받을지(`scope`) · `state`
    - ② `state` 난수를 만들어 세션에 넣어 두고, 돌아왔을 때 같은 값인지 대조한다.
      이게 없으면 공격자가 **자기 코드로 남을 자기 계정에 로그인시킬 수 있다**
    - ③ 돌아온 **1회용 코드**를 구글 서버에 보내 토큰으로 바꾼다.
      이때 브라우저를 거치지 않고 **서버끼리** 주고받는다 — 값이 주소창에 남지 않는다
    - ④ 그 토큰으로 사용자 정보를 받아 온다
  - **제공자마다 다른 응답을 같은 모양으로 정리해 준다.**
    구글은 계정 번호를 `sub` 라 부르고 깃허브는 `id` 라 부르는데,
    우리 코드는 양쪽 다 `$user->getId()` 로 읽는다. 나중에 깃허브를 더해도 우리 코드는 그대로다

### 알림

- **Notification + Mail 채널**
  - 클래스 하나에 **"누구에게 무엇을 보낼지"만** 적는다
  - 어느 통로로 보낼지(`via()`)를 고르면 — 메일·DB·슬랙 — 실제 발송은 프레임워크가 한다
  - 메일 서버 연결, 재시도, HTML 틀은 우리가 손대지 않는다

- **서명된 URL** — `URL::signedRoute()` + `signed` 미들웨어
  - 주소 뒤에 **서명**을 붙인다. 주소를 한 글자라도 고치면 미들웨어가 **403**으로 막는다
  - 만료 시각도 함께 서명할 수 있다(`temporarySignedRoute`)
  - **로그인 없이 누르는 링크**를 안전하게 만들 수 있다 — 메일 속 링크가 그렇다

### 큐 · 예약

- **큐** — `ShouldQueue` 인터페이스
  - 클래스에 이 인터페이스를 붙이면 **그 자리에서 실행하지 않는다.**
    '할 일' 표(`jobs`)에 한 줄 적고 요청은 곧바로 끝난다
  - 별도로 도는 **워커**가 그 줄을 꺼내 실제로 실행한다

  **자료구조 '큐'와 무엇이 다른가**

  - 자료구조 큐는 **순서**만 정한다. 먼저 넣은 것이 먼저 나온다, 그뿐이다
  - 그걸 배열로 만들어 봐야 **PHP 에서는 쓸모가 없다.**
    요청이 끝나면 프로세스가 죽고, 메모리에 든 큐도 같이 사라진다.
    "나중에 할 일"을 배열에 담아 두면 응답을 보내는 순간 없어진다
  - 그래서 라라벨 큐가 실제로 하는 일은 순서 관리가 아니라 **요청과 실행을 떼어 놓는 것**이다

  | | 자료구조 큐 | 라라벨 큐 |
  |---|---|---|
  | 어디에 있나 | 프로그램 메모리 | **DB · Redis** (요청이 끝나도 남는다) |
  | 누가 꺼내나 | 같은 프로그램 | **다른 프로세스**(워커) |
  | 서버가 꺼지면 | 사라진다 | **남아 있다.** 워커가 다시 뜨면 이어서 한다 |
  | 실패하면 | 개념에 없다 | 정해진 횟수만큼 재시도, 끝내 실패하면 `failed_jobs` 에 보관 |
  | 둘이 동시에 꺼내면 | 개념에 없다 | `reserved_at` 으로 잠가 **같은 일을 두 번 하지 않는다** |
  | 예약 | 개념에 없다 | `available_at` 으로 "10초 뒤에 해라"가 된다 |

  > 이름이 '큐'인 이유는 꺼내는 순서가 들어온 순서라서다.
  > 하지만 **쓸모는 순서가 아니라 '요청 바깥에 남는다'는 데서 나온다.**

- **예약 작업** — `Schedule::command()`
  - **"무엇을 언제"** 를 한 파일에 적어 둔다
  - 바깥에서 1분마다 한 번만 깨워 주면, 시각을 보고 해당하는 것만 실행한다
  - 할 일이 늘어도 바깥에 등록할 것은 그대로 하나다

### 목록 · 파일 · 글

- **페이징** — `paginate()` / `cursorPaginate()`
  - 전체 개수를 세고, `LIMIT`/`OFFSET` 을 붙여 **그 쪽 몫만** 가져온다
  - 페이지 번호 HTML 도 만들어 준다 (`$posts->links()`)
  - `cursorPaginate()` 는 번호 대신 **'마지막으로 본 줄'** 을 기준으로 다음을 가져온다

- **파일 업로드 검증·저장**
  - `image` · `mimes:jpeg,png` · `max:16384` 같은 규칙으로 받은 파일을 검사한다
  - 확장자만 보는 것이 아니라 **실제 내용**을 본다 (이름만 `.jpg` 인 파일은 걸린다)

- **마크다운** — `Str::markdown()`
  - 마크다운으로 쓴 글을 HTML 로 바꾼다
  - `html_input: 'escape'` 를 주면 글 안에 든 태그를 **글자로** 만든다 — 남이 심은 스크립트가 돌지 않는다

- **소프트 삭제** — `SoftDeletes` 트레이트(trait)
  - **트레이트** = 여러 클래스가 나눠 쓰는 코드 묶음. `use SoftDeletes;` 한 줄로 가져다 쓴다
  - `delete()` 가 줄을 없애는 대신 `deleted_at` 에 **시각만 찍는다**
  - 그 뒤로는 모든 조회에 `deleted_at is null` 이 자동으로 붙어 화면에서 사라진다
  - `restore()` 로 되돌리고, `withTrashed()` 로 필요할 때만 다시 꺼낸다

### 후보에 올렸다가 뺀 것

- **Scout** — `laravel/scout` **(공식 패키지)**. 모델을 검색 엔진(Algolia · Meilisearch · DB)에 이어 `Model::search()` 한 줄로 검색하게 한다
- **캐시** — `Cache::remember('키', 초, fn () => 무거운계산())`. 없으면 계산해 저장하고, 있으면 저장된 것을 준다
- **Broadcasting** — 서버에서 일어난 일을 접속 중인 브라우저에 실시간으로 밀어 준다. WebSocket 서버가 따로 필요하다
- **Fortify** — `laravel/fortify` **(공식 패키지)**. 로그인·가입·2단계 인증의 뒷단 처리를 통째로 제공한다

> 왜 뺐는지는 **2단계**에 적었다.

## 2단계 — 무엇을 만들 수 있는가

목록을 놓고 **"이 서비스에 실제로 필요한가"** 를 물었다.
리뷰 커뮤니티라는 성격, 그리고 **지금 데이터 규모**가 기준이었다.

### 실제 규모 (측정값)

| | |
|---|---|
| 회원 | 25명 |
| 글 | 193개 (15개씩 → 13쪽) |
| 작품 게시판 | 6개, 가장 큰 곳 44개 (3쪽) |
| 글당 댓글 | 최다 4개 (1쪽) |

이 숫자가 **넣을 것과 뺄 것을 갈랐다.**

### 넣기로 한 것

| 기능 | 근거 |
|---|---|
| 비밀번호 찾기 | 이메일 없이는 계정을 영영 잃는다 |
| 이메일 인증 | 주소를 안 믿으면 남의 주소로 알림이 간다 |
| 댓글 알림 메일 | 커뮤니티의 핵심 — 내 글에 반응이 오면 알아야 한다 |
| 본문 사진 | 리뷰에 장면 캡처가 없으면 밋밋하다 |
| 큐 | 메일 발송이 사용자를 3.8초 붙잡고 있었다 (측정) |
| 예약 작업 | 버려진 사진이 쌓이는데 치우는 사람이 없었다 |
| 구글 로그인 | 가입 장벽 |
| 회원 탈퇴 | 쿠키 동의까지 만들어 놓고 탈퇴가 없었다 |

### 빼기로 한 것 — 이유가 더 중요하다

| 기능 | 왜 뺐나 |
|---|---|
| 무한 스크롤 (`cursorPaginate`) | 가장 큰 게시판이 **3쪽**이다. `offset`이 느려지는 구간에 도달하지 못한다 |
| Scout 검색 | MariaDB에 **ngram 파서가 없어** 한국어 FULLTEXT가 동작하지 않는다 (실측: `봉준호` 0건, `director` 정상). FULLTEXT 없이 Scout를 쓰면 지금과 **같은 `LIKE` 질의**가 나간다 — 설치했다가 되돌렸다 |
| 캐시 | 랭킹 질의가 **1~2ms**다 (측정). 줄일 여지가 없다 |
| 계정 연동 | 연결 해제 시 계정이 잠기지 않게 막는 일까지 딸려 온다. 회원 25명 규모에 치를 비용이 아니다 |
| 데이터 내보내기 | 법적 요구에 가깝고 이 서비스의 사용자 가치가 낮다 |

> **"기능을 정당화하려고 데이터를 늘리지 않았다."**
> 5만 건을 넣으면 무한 스크롤이 필요해 보이게 만들 수 있지만, 그건 순서가 거꾸로다.

## 3단계 — 실제로 구현한 것

각 기능마다 **라라벨이 한 일**과 **우리가 한 일**을 갈라 적는다.
기능은 우리가 정하는 것이고, 라라벨은 그 기능을 만들 장치를 줄 뿐이다.
장치를 거의 안 쓴 것도 있다 — 그것도 그대로 적는다.

---

### ① 페이징 (이관 단계)

- **라라벨** — `paginate($perPage)` 한 줄이 전체 개수 세기 · `LIMIT`/`OFFSET` · 페이지 번호 계산 · 번호 HTML 생성까지 한다
- **우리** — 한 쪽 개수를 쿠키에서 읽는 것, `?page=999` 를 마지막 쪽으로 돌리는 것, 레거시 마크업에 맞춘 번호 화면

화면 코드는 `{{ $posts->links() }}` 한 줄이다. 출력 HTML만 우리 것으로 바꿔 끼웠다(`Paginator::defaultView`).
처음/마지막 버튼, `1 2 … 6 7 8 … 12 13` 생략 표기가 여기서 나온다.

---

### ② 메일 — 네 종류

| 메일 | 언제 | 끌 수 있나 |
|---|---|---|
| 비밀번호 찾기 | 본인 요청 | — |
| 이메일 인증 | 주소를 넣거나 바꿀 때 | — |
| 댓글·답글 알림 | 내 글/댓글에 반응 | **켠 경우에만 발송** |
| 새 기기 로그인 · 비밀번호 변경 | 그 일이 일어날 때 | **끌 수 없음** |

- **라라벨** — 토큰 발급·검증·폐기(비밀번호 찾기), 인증 링크의 서명과 만료,
  메일 서버 연결·재시도·HTML 틀, 서명된 주소 검사(`signed` 미들웨어)
- **우리** — 언제 보낼지, 무슨 문구를 보낼지, 누구에게 보내도 되는지

**보안 알림을 끌 수 없게 한 것은 우리 판단이다.** 본인이 하지 않은 일을 알리는 통로라서,
끄면 알림의 목적이 사라진다.

**막는 지점이 셋이다** — 화면(체크박스 잠금) · 저장(`hasVerifiedEmail()`) · **발송 직전**.
메일이 실제로 나가는 곳에서 한 번 더 본다. 인증하지 않은 주소로는 한 통도 나가지 않는다.

**수신거부 링크** — 로그인 없이 알림을 끈다. `URL::signedRoute` + `signed` 미들웨어.
주소를 한 글자만 고쳐도, `id` 를 바꿔 남의 알림을 끄려 해도 **403**. 이 검사는 우리가 짜지 않았다.

### ③ 큐 — 숫자가 있는 개선

실제 SMTP 로 바꾸자 **댓글 작성이 느려졌다.** 메일 한 통에 3.82초가 걸리고 그동안 화면이 멈춰 있었다.

| 댓글 작성 응답 시간 | |
|---|---|
| `sync` (그 자리에서 발송) | **4.63초** |
| `database` (큐에 적어 두기) | **0.16초** |

- **라라벨** — '할 일' 표에 적어 두기, 워커가 꺼내 실행, 실패 시 재시도, 끝내 실패한 것 보관
- **우리** — 알림 클래스에 `implements ShouldQueue` **한 줄씩**, `.env` 한 줄, 워커 실행 스크립트

**"무엇을 보낼지" 적어 둔 코드는 하나도 바뀌지 않았다.**
프레임워크 제공 메일(`VerifyEmail`·`ResetPassword`)은 고칠 수 없어, 물려받아 그 한 줄만 붙인 껍데기를 만들었다.

> 이 항목이 **라라벨을 썼다고 말하기 가장 쉬운 사례**다. 우리가 고친 것은 한 줄이고 결과는 30배다.

### ④ 예약 작업

| 시각 | 하는 일 |
|---|---|
| 04:10 | 어느 글에도 쓰이지 않는 업로드 사진 삭제 |
| 04:20 | 실패한 작업 기록을 일주일치만 유지 |
| 04:30 | 유예 기간이 지난 탈퇴 계정의 개인정보 삭제 |

- **라라벨** — 시각표를 읽고 해당하는 것만 실행, 겹쳐 돌지 않게 막기(`withoutOverlapping`)
- **우리** — 무엇을 언제 할지, 지울 대상을 고르는 규칙

바깥에서 1분마다 한 번만 깨워 주면 된다. **할 일이 늘어도 바깥에 등록할 것은 그대로 하나다.**
"지우겠다고 약속한 것을 실제로 지우는 자리"이고, 사람이 기억해서 하는 일로 두면 결국 안 하게 된다.

### ⑤ 구글 로그인 — 공식 패키지 `laravel/socialite`

- **라라벨(Socialite)** — 보낼 주소 만들기, `state` 발급·대조, 1회용 코드를 토큰으로 교환,
  구글에 사용자 정보 요청, 결과를 객체로 정리
- **우리** — 돌아온 사람을 우리 표와 **어떻게 이을지**

**코드가 이만큼 줄었다**

```php
// 보낼 때 — 주소 조립·state 발급을 우리가 하던 것
$state = bin2hex(random_bytes(16));
$request->session()->put(self::STATE_KEY, $state);
return self::AUTH_URL . '?' . http_build_query([... 7개 항목 ...]);

// Socialite
return Socialite::driver('google')->with(['prompt' => 'select_account'])->redirect();
```

돌아올 때는 차이가 더 크다. `state` 대조 · 코드를 토큰으로 교환 · 사용자 정보 요청 · 결과 정리를
**`Socialite::driver('google')->user()` 한 줄**이 한다. 우리가 짰던 서비스 파일 140줄이 사라졌다.

**처음에는 설치하지 못했다** — 그 과정도 기록해 둔다

- `league/oauth1-client` 이 Guzzle 6/7 을 요구하는데 이 프로젝트는 **Guzzle 8** 에 고정되어 있었다
- `firebase/php-jwt` 가 보안 권고에 걸려 composer 가 설치를 거부했다

여기서 **OAuth 를 직접 구현하는 쪽으로 한 번 갔다가 되돌아왔다.**
`--with-all-dependencies`(`-W`) 를 붙이면 composer 가 **다른 패키지의 판까지 함께 조정**한다.

| | 전 | 후 |
|---|---|---|
| `guzzlehttp/guzzle` | 8.2.0 | **7.15.5** (라라벨이 둘 다 지원) |
| `laravel/framework` | 13.31.0 | 13.32.0 |
| `firebase/php-jwt` | 설치 거부 | **v7.1.1** (권고에 걸리지 않는 판) |

> **배운 것** — "패키지가 안 깔린다"는 대개 '못 쓴다'가 아니라 '조건을 조정해야 한다'는 뜻이다.
> 보안 경고를 끄는 선택지도 있었지만, 걸리지 않는 판이 이미 있었다.

**설계 판단 셋** (Socialite 로 바꾼 뒤에도 그대로다)

1. **이메일이 아니라 계정 번호(`sub`)로 잇는다** — 사람은 구글 계정의 이메일을 바꿀 수 있다. 주소로 이어 두면 그 순간 남이 된다
2. **기존 계정과 자동으로 잇지 않는다** — 구글 버튼을 눌렀는데 아이디로 만든 계정에 로그인되는 것은 예상 밖의 일이다
3. **이메일은 자리가 비었을 때만 채운다** — `users.email` 은 메일 알림 기능의 칸이다. 그 칸의 제약 때문에 로그인이 막혀서는 안 된다

**가입 전 동의 화면** — 구글에서 받은 동의는 "구글이 우리에게 정보를 넘겨도 되는가"이고,
우리가 그 정보를 무슨 목적으로 쓰는가는 우리가 따로 받아야 한다. 계정을 만들기 **전에** 묻는다.

**비밀번호 없는 계정의 본인 확인** — 구글 회원에게는 확인할 비밀번호가 없다.
`prompt=login` 을 함께 보내 **구글이 비밀번호를 다시 묻게** 한다.
이 값을 빼면 구글에 로그인된 상태에서 아무것도 묻지 않고 통과한다 —
확인이 막으려는 상황(자리를 비운 사이 남이 들어옴)에서 그 사람도 통과하게 된다.

### ⑥ 회원 탈퇴

> 라라벨이 준 것은 **두 가지**다 — 소프트 삭제와 예약 작업. 나머지는 우리 판단이다.

| 때 | 무슨 일 |
|---|---|
| 즉시 | `deleted_at` 표시, 로그인 차단, 모든 기기 세션 해제 |
| 30일 이내 | 다시 로그인하면 **복구할지 지울지 선택** |
| 30일 후 | 아이디·이메일·구글 연결·아바타 삭제 (되돌릴 수 없음) |

- **라라벨** — `SoftDeletes`(`delete()` 가 시각만 찍고, 이후 조회에 `deleted_at is null` 자동 적용,
  `restore()` · `withTrashed()`), 30일 뒤 실행을 맡는 예약 작업
- **우리** — 무엇을 남기고 무엇을 지울지, 유예 기간 길이, 복구 확인 화면, 아이디 입력 확인

**글과 댓글은 남긴다.** 작성자만 '탈퇴한 사용자'로 보인다.
커뮤니티의 글은 혼자 쓴 것이 아니라 대화라서, 지우면 남의 글에 달린 흐름이 끊긴다 (Reddit 도 같은 방식).

DB 도 같은 말을 한다 — `posts.author_id` 가 `RESTRICT` 라 글이 있는 회원은 애초에 삭제되지 않는다.
**제약을 피해 간 것이 아니라 제약과 설계가 같은 말을 하고 있다.**

`deleted_at` 만 찍는 것은 '감추기'지 '지우기'가 아니다. 개인정보는 DB 에 그대로 읽을 수 있게 남는다.
그래서 두 단계로 나눴다.

**이름 하나를 바꾸는 방법** — 화면 19곳에서 작성자 이름을 쓴다. 그 자리들을 고치는 대신
**이름을 내주는 지점 한 곳**에서 바꿨다(접근자). 빠뜨릴 자리가 생기지 않고, 되돌리면 원래 이름이 돌아온다.

**조용한 복구를 막았다** — 저장된 비밀번호로 습관처럼 로그인하면 계정이 말없이 살아난다.
본인은 지운 줄 아는데 살아 있는 것이라, 한 번 묻고 고르게 한다.

### ⑦ 약관 · 동의 기록

가입에 동의 절차가 없었다. 쿠키 동의는 배너까지 만들어 두고 정작 회원가입에는 아무것도 없었다.

- **라라벨** — `accepted` 검증 규칙 정도. 거의 쓰지 않았다
- **우리** — 문서 내용, 기록 설계

- `/terms`, `/privacy` — **이미 구현된 것을 그대로 적었다.** 보관 기간 표가 곧 ⑥의 설계다
- 동의를 **기록**한다. 체크박스만 두면 "동의를 받았다"고 말할 근거가 없다
- 쿠키 동의와 **같은 표**(`consent_log`)에 쌓는다. `source` 로 구분 (`signup` / `google`)

### 정리 — 라라벨 의존도

| 기능 | 라라벨이 한 일 | 우리가 한 일 |
|---|---|---|
| 큐 | **거의 전부** | 한 줄씩 붙이기 |
| 비밀번호 찾기 | **거의 전부** | 화면 네 개 |
| 이메일 인증 | **대부분** (링크·서명·만료) | 언제 보낼지, 어디서 막을지 |
| 메일 알림 | 발송 · 재시도 · 틀 | 문구, 보낼 조건 |
| 페이징 | 계산 전부 | 화면 모양, 한 쪽 개수 |
| 예약 작업 | 시각표 실행 | 무엇을 언제, 지울 규칙 |
| 구글 로그인 | **OAuth 절차 전부** (Socialite) | 우리 표와 잇는 규칙 |
| 회원 탈퇴 | 소프트 삭제 · 예약 | **설계 전부** |
| 약관 동의 | 검증 규칙 하나 | **거의 전부** |

위로 갈수록 "프레임워크를 써서 얻은 것"이 뚜렷하고, 아래로 갈수록 "프레임워크 위에서 우리가 만든 것"이다.
**둘 다 필요하다** — 프레임워크는 기능을 주지 않는다. 기능을 만들 장치를 줄 뿐이다.
